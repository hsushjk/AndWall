## AndWall क्यों अस्तित्व में आया

[ShizuWall](https://github.com/AhmetCanArslan/ShizuWall) एक बहुत अच्छा प्रोजेक्ट है: शक्तिशाली, परंतु फुलाया हुआ नहीं; इसका UI डिज़ाइन सुंदर और तर्कसंगत है। लेकिन यह VPN मोड का समर्थन नहीं करता।

इस फ़ोर्क रिपॉज़िटरी के मालिक का मानना है कि अच्छा प्रोजेक्ट समावेशी होना चाहिए। VPN बैकएंड जोड़ने से उपयोग की दहलीज़ भले ही कम हो जाती है, पर इससे ऊपरी सीमा नीचे नहीं आती।

## AndWall क्यों चुनें

- **कई मोड उपलब्ध**: आप सबसे बुनियादी VPN का उपयोग कर सकते हैं। अधिक शक्तिशाली Shizuku, ADB, root मोड का भी उपयोग कर सकते हैं।
- **प्रति-ऐप नियंत्रण**: ऐप के अनुसार नेटवर्क अवरुद्ध करें; चेन मोड में इसमें वर्क प्रोफ़ाइल और क्लोन प्रतियाँ भी शामिल हैं।
- **गोपनीयता**: ऑफ़लाइन-प्रथम, कोई एनालिटिक्स नहीं, कोई टेलीमेट्री नहीं, कोई रिमोट VPN सर्वर नहीं — टनल पूरी तरह स्थानीय है और सभी पैकेट छोड़ दिए जाते हैं।
- **त्वरित पहुँच**: क्विक सेटिंग टाइल, विजेट और फ़्लोटिंग बटन।
- **ऑटोमेशन**: adb, Tasker, MacroDroid आदि से भेजे गए ब्रॉडकास्ट के माध्यम से नियंत्रण।

## इस फ़ोर्क में मुख्य बदलाव

AndWall, [ShizuWall](https://github.com/AhmetCanArslan/ShizuWall) का फ़ोर्क है। इस फ़ोर्क में निम्नलिखित जोड़ा गया है:

- **VPN बैकएंड**: बिना कॉन्फ़िगरेशन वाला फ़ायरवॉल बैकएंड — उपयोग के लिए केवल सिस्टम प्राधिकरण डायलॉग की पुष्टि करनी होती है।
- **VPN मोड के लिए UI अनुकूलन**: उन फ़ायरवॉल मोड और सुविधाओं को छिपाना जो VPN बैकएंड प्रदान नहीं कर सकता, तथा फ़ायरवॉल मोड को व्हाइटलिस्ट पर वापस लाना।
- **रीब्रांडिंग, अद्यतन सेटिंग्स और अनुवाद**, साथ ही इस फ़ोर्क के लिए अधिक विस्तृत चेंजलॉग और अपडेट जाँच।
- **गोपनीयता नीति हटाई गई**: यह प्रोजेक्ट किसी भी ऐप स्टोर पर प्रकाशित नहीं होता और व्यक्तिगत डेटा संसाधित नहीं करता, इसलिए सूचना देने का कोई दायित्व उत्पन्न नहीं होता।

## संगत वातावरण

Android 11 या उससे ऊपर, तथा निम्नलिखित में से कोई एक बैकएंड आवश्यक है:

- **VPN**
- **Shizuku** (फ़ोर्क संस्करण समर्थित)

- **Root**

## यह कैसे काम करता है

केवल Shizuku, LibADB और Root बैकएंड को विशेषाधिकार-प्राप्त सहायक कंपोनेंट की आवश्यकता होती है। ये Android connectivity के **chain 3** को संचालित करते हैं, जो पैकेज नाम के आधार पर नेटवर्क एक्सेस नियंत्रित करने वाला प्लेटफ़ॉर्म तंत्र है:

```bash
cmd connectivity set-chain3-enabled true                                # फ़ायरवॉल चालू करें
cmd connectivity set-package-networking-enabled false <package.name>   # अवरुद्ध करें
cmd connectivity set-package-networking-enabled true <package.name>    # अवरोध हटाएँ
cmd connectivity set-chain3-enabled false                               # फ़ायरवॉल बंद करें
```

Android डिवाइस रीबूट होने पर इन नियमों को साफ़ कर देता है।

### VPN बैकएंड

VPN बैकएंड एक स्थानीय `VpnService` tun डिवाइस है जो केवल उन ऐप्स को पकड़ता है जिन्हें आप अवरुद्ध करने के लिए चुनते हैं, और उसे प्राप्त होने वाले सभी पैकेट छोड़ देता है। इसे केवल एक बार सिस्टम प्राधिकरण डायलॉग की आवश्यकता होती है, कोई अन्य कॉन्फ़िगरेशन नहीं। नए इंस्टॉल डिफ़ॉल्ट रूप से इस बैकएंड का उपयोग **व्हाइटलिस्ट** फ़ायरवॉल मोड के साथ करते हैं (जिन ऐप्स को नेटवर्क की अनुमति है उन्हें चुनें, बाकी सभी अवरुद्ध), जिसे **सेटिंग्स → बैकएंड और वर्क मोड** में बदला जा सकता है।

रीबूट के बाद टनल स्वचालित रूप से पुनः आरंभ हो जाती है; यदि फ़ायरवॉल चालू रहते हुए ऐप प्रोसेस समाप्त हो जाए, तो अगली बार AndWall खोलने पर सुरक्षा बहाल हो जाती है। जब तक डिवाइस पर स्क्रीन लॉक सेट है, लॉकस्क्रीन मोड समर्थित है (टनल स्क्रीन लॉक की स्थिति का पालन करती है)।

VPN बैकएंड की सीमाएँ: यह केवल वर्तमान उपयोगकर्ता के ऐप्स संभालता है (वर्क प्रोफ़ाइल/क्लोन प्रतियाँ समर्थित नहीं हैं), केवल-मोबाइल-डेटा नियम और फ़ोरग्राउंड पहचान आधारित मोड समर्थित नहीं हैं, तथा अवरुद्ध ऐप सेट का रखरखाव UID-आधारित फ़ायरवॉल चेन पर निर्भर नहीं करता। यदि आपको ये सुविधाएँ चाहिए, तो Shizuku, LibADB या Root का उपयोग जारी रखें।

## ऑटोमेशन

प्रत्येक ब्रॉडकास्ट के लिए एक सक्रिय बैकएंड आवश्यक है। `apps` ऐप कुंजियों की अल्पविराम-पृथक सूची है: केवल पैकेज नाम का अर्थ उपयोगकर्ता 0 है, और उपसर्ग वाला नाम (जैसे `150:com.example.app`) उस वर्क प्रोफ़ाइल या क्लोन स्पेस में उसकी प्रति दर्शाता है।

### फ़ायरवॉल: `shizuwall.CONTROL`

| पैरामीटर | प्रकार | |
|---|---|---|
| `state` | boolean, अनिवार्य | `true` = अवरुद्ध करें, `false` = अवरोध हटाएँ |
| `apps` | string, वैकल्पिक | अवरुद्ध या अवरोध-मुक्त करने वाले ऐप। छोड़े जाने पर ब्रॉडकास्ट पूरा फ़ायरवॉल चालू/बंद कर देता है। |

```bash
# फ़ायरवॉल चालू करें (state false का अर्थ बंद करना)
adb shell am broadcast -a shizuwall.CONTROL -n com.arslan.shizuwall/.receivers.FirewallControlReceiver --ez state true

# किसी ऐप और उसकी वर्क प्रोफ़ाइल में उसकी प्रतियों को अवरुद्ध करें (state false का अर्थ अवरोध हटाना)
adb shell am broadcast -a shizuwall.CONTROL -n com.arslan.shizuwall/.receivers.FirewallControlReceiver --ez state true --es apps "com.example.app,150:com.example.app"
```

`apps` के साथ, ऐप के भीतर का चयन समन्वयित रहता है: `state true` इन ऐप्स को चयनित करता है और यदि फ़ायरवॉल पहले से बंद था तो उसे चालू कर देता है; `state false` चयन हटाता है और फ़ायरवॉल चालू रखता है। व्हाइटलिस्ट मोड में `apps` अनुमत सूची को इंगित करता है, इसलिए इन दोनों स्थितियों का अर्थ उल्टा हो जाता है।

VPN मोड में ब्रॉडकास्ट वैसे ही काम करते हैं, लेकिन `apps` को केवल वर्तमान उपयोगकर्ता के ऐप्स का संदर्भ देना चाहिए; वर्क प्रोफ़ाइल की कुंजियाँ छोड़ दी जाती हैं।

### नया ऐप: `shizuwall.APP_INSTALLED`

नए इंस्टॉल किए गए ऐप को रिपोर्ट करें, ताकि नए ऐप की नीति और सूचनाएँ वैसे ही लागू हों जैसे AndWall ने स्वयं इंस्टॉल का पता लगाया हो। AndWall केवल उसी उपयोगकर्ता प्रोफ़ाइल में इंस्टॉल देख सकता है जिसमें वह स्वयं है, इसलिए अन्य प्रोफ़ाइल के लिए इसी तरीके से कवरेज आवश्यक है।

```bash
adb shell am broadcast -a shizuwall.APP_INSTALLED -n com.arslan.shizuwall/.receivers.AppInstalledReceiver --es apps "com.example.newapp"
```

फ़ायरवॉल बंद होने पर कोई नियम लागू नहीं होता। जिन ऐप्स के पास `INTERNET` अनुमति नहीं है, उन्हें अनदेखा किया जाता है।

### प्रोफ़ाइल: `shizuwall.PROFILE`

सहेजी गई प्रोफ़ाइल सक्रिय करें: उस प्रोफ़ाइल के ऐप चयन, फ़ायरवॉल मोड, प्रति-ऐप मोड और *सिस्टम ऐप दिखाएँ* सेटिंग लागू करें।

| पैरामीटर | प्रकार | |
|---|---|---|
| `profile` | string | प्रोफ़ाइल नाम, प्रोफ़ाइल पैनल में दिखाए गए नाम के अनुरूप। |
| `profile_id` | string | आंतरिक ID; इसकी जाँच पहले की जाती है और यह नाम बदलने से प्रभावित नहीं होता। उस प्रोफ़ाइल के **ऑटोमेशन** डायलॉग में तैयार कमांड दिखाई देता है। |
| `force_enable` | boolean, वैकल्पिक | टॉगल करने पर फ़ायरवॉल चालू हो जाता है, भले ही वह पहले बंद था। |

`profile` और `profile_id` में से कम से कम एक दें। यदि दोनों में से कोई भी मेल नहीं खाता, तो कुछ भी नहीं बदलेगा और toast के माध्यम से सूचित किया जाएगा।

```bash
adb shell am broadcast -a shizuwall.PROFILE -n com.arslan.shizuwall/.receivers.ProfileControlReceiver --es profile "Work"
```

## स्रोत से बिल्ड करें

यह प्रोजेक्ट Gradle Wrapper और Android SDK से बिल्ड होता है:

```bash
./gradlew assembleDebug
```

डिबग बिल्ड `.debug` सफ़िक्स का उपयोग करता है और रिलीज़ संस्करण के साथ-साथ इंस्टॉल किया जा सकता है। रिलीज़ बिल्ड के लिए आपको अपना साइनिंग कॉन्फ़िगरेशन चाहिए।

## अस्वीकरण

AndWall **“जैसा है वैसा”** प्रदान किया जाता है, बिना किसी गारंटी के। यह उन्नत सिस्टम अनुमतियों पर निर्भर करता है, और डेवलपर सिस्टम अस्थिरता, डेटा हानि या नेटवर्क अवरोध से होने वाले दुष्प्रभावों के लिए उत्तरदायी नहीं है। कृपया अवश्य जाँचें कि आपने किन ऐप्स को अवरुद्ध किया है।

यह फ़ोर्क केवल [इस GitHub रिपॉज़िटरी](https://github.com/hsushjk/AndWall) के माध्यम से वितरित किया जाता है। अन्य स्रोतों से प्राप्त APK का इस प्रोजेक्ट से कोई संबंध नहीं है, उपयोग अपने जोखिम पर करें। AndWall की कोई आधिकारिक वेबसाइट नहीं है और यह Google Play या F-Droid पर प्रकाशित नहीं होता।

`INTERNET` अनुमति केवल वायरलेस डीबगिंग पेयरिंग (LibADB) के लिए है।
