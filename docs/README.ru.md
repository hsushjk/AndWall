## Почему появился AndWall

[ShizuWall](https://github.com/AhmetCanArslan/ShizuWall) — очень хороший проект: функциональный, но без лишнего веса, с красивым и продуманным дизайном интерфейса. Но он не поддерживает режим VPN.

Владелец этого форка считает, что хороший проект должен вбирать в себя лучшее. Интеграция VPN-бэкенда хоть и снижает порог входа, но не снижает потолок.

## Почему стоит выбрать AndWall

- **Несколько режимов на выбор**: можно использовать самый базовый VPN. Также доступны более мощные режимы Shizuku, ADB и root.
- **Контроль по приложениям**: блокировка сети по приложениям, а в цепном режиме — также рабочие профили и клонированные копии.
- **Конфиденциальность**: приоритет офлайн-работы, без аналитики, без телеметрии, без удалённых VPN-серверов — туннель полностью локальный, все пакеты отбрасываются.
- **Быстрый доступ**: плитка в быстрых настройках, виджеты и плавающая кнопка.
- **Автоматизация**: управление через широковещательные сообщения от adb, Tasker, MacroDroid и других.

## Основные изменения в этом форке

AndWall — это форк [ShizuWall](https://github.com/AhmetCanArslan/ShizuWall). В этом форке добавлено:

- **VPN-бэкенд**: бэкенд брандмауэра без настройки — достаточно подтвердить системный диалог авторизации.
- **Адаптация интерфейса для режима VPN**: скрытие режимов и функций брандмауэра, которые не может предоставить VPN-бэкенд, и откат режима брандмауэра на белый список.
- **Ребрендинг, обновлённые настройки и переводы**, а также более подробный журнал изменений и проверка обновлений для этого форка.
- **Удалена политика конфиденциальности**: проект не публикуется ни в одном магазине приложений и не обрабатывает персональные данные, поэтому обязанность информирования не возникает.

## Совместимые окружения

Android 11 и выше, а также любой из следующих бэкендов:

- **VPN**
- **Shizuku** (поддерживаемые сборки форка)
- **LibADB**: сопряжение через беспроводную отладку, компьютер не нужен
- **Root**

## Принцип работы

Только бэкендам Shizuku, LibADB и Root нужен привилегированный сопутствующий компонент. Они работают с **chain 3** в Android connectivity — это платформенный механизм управления сетевым доступом по имени пакета:

```bash
cmd connectivity set-chain3-enabled true                                # включить брандмауэр
cmd connectivity set-package-networking-enabled false <package.name>   # заблокировать
cmd connectivity set-package-networking-enabled true <package.name>    # снять блокировку
cmd connectivity set-chain3-enabled false                               # выключить брандмауэр
```

Android удаляет эти правила после перезагрузки устройства.

### VPN-бэкенд

VPN-бэкенд — это локальное tun-устройство `VpnService`, которое перехватывает только выбранные вами для блокировки приложения и отбрасывает все полученные пакеты. Ему нужен лишь один системный диалог авторизации, никакой другой настройки не требуется. При новой установке по умолчанию используется этот бэкенд вместе с режимом брандмауэра **белый список** (выберите приложения, которым разрешён доступ в сеть, остальные блокируются); изменить это можно в **Настройки → Бэкенд и рабочий режим**.

После перезагрузки туннель запускается автоматически; если процесс приложения будет завершён при включённом брандмауэре, защита восстановится при следующем открытии AndWall. Если на устройстве установлена блокировка экрана, поддерживается режим блокировки экрана (туннель следует за состоянием блокировки).

Ограничения VPN-бэкенда: он обрабатывает только приложения текущего пользователя (рабочие профили и клонированные копии не поддерживаются), не поддерживает правила только для мобильных данных и режимы на основе определения переднего плана, а поддержка набора заблокированных приложений не опирается на цепочки брандмауэра по UID. Если нужны эти функции, продолжайте использовать Shizuku, LibADB или Root.

## Автоматизация

Каждому широковещательному сообщению нужен активный бэкенд. `apps` — это список ключей приложений через запятую: только имя пакета означает пользователя 0, а с префиксом (например, `150:com.example.app`) — копию в этом рабочем профиле или пространстве клонирования.

### Брандмауэр: `shizuwall.CONTROL`

| Параметр | Тип | |
|---|---|---|
| `state` | boolean, обязательный | `true` = блокировать, `false` = разблокировать |
| `apps` | string, необязательный | Приложения, которые нужно заблокировать или разблокировать. Если опустить, широковещательное сообщение включит или выключит весь брандмауэр. |

```bash
# включить брандмауэр (state false означает выключить)
adb shell am broadcast -a shizuwall.CONTROL -n com.arslan.shizuwall/.receivers.FirewallControlReceiver --ez state true

# заблокировать приложение и его копию в рабочем профиле (state false снимает блокировку)
adb shell am broadcast -a shizuwall.CONTROL -n com.arslan.shizuwall/.receivers.FirewallControlReceiver --ez state true --es apps "com.example.app,150:com.example.app"
```

При указании `apps` выбор в приложении синхронизируется: `state true` выберет эти приложения и включит брандмауэр, если он был выключен; `state false` снимет выбор и оставит брандмауэр включённым. В режиме белого списка `apps` указывает на список разрешённых, поэтому эти два состояния означают обратное.

В режиме VPN широковещательные сообщения работают так же, но `apps` должен ссылаться только на приложения текущего пользователя; ключи рабочих профилей пропускаются.

### Новое приложение: `shizuwall.APP_INSTALLED`

Сообщает о новом установленном приложении, чтобы политика для новых приложений и уведомления срабатывали так же, как если бы AndWall сам обнаружил установку. AndWall видит установки только в своём профиле пользователя, поэтому другие профили нужно охватывать этим способом.

```bash
adb shell am broadcast -a shizuwall.APP_INSTALLED -n com.arslan.shizuwall/.receivers.AppInstalledReceiver --es apps "com.example.newapp"
```

При выключенном брандмауэре правила не применяются. Приложения без разрешения `INTERNET` игнорируются.

### Профили: `shizuwall.PROFILE`

Активирует сохранённый профиль: применяет выбор приложений, режим брандмауэра, режим для каждого приложения и параметр *показывать системные приложения* этого профиля.

| Параметр | Тип | |
|---|---|---|
| `profile` | string | Имя профиля, совпадающее с именем на панели профилей. |
| `profile_id` | string | Внутренний ID; проверяется в первую очередь и не зависит от переименования. Готовая команда отображается в диалоге **автоматизации** этого профиля. |
| `force_enable` | boolean, необязательный | Включает брандмауэр после переключения, даже если он был выключен. |

Нужно указать хотя бы одно из `profile` и `profile_id`. Если ни одно не совпадёт, ничего не изменится, и появится подсказка toast.

```bash
adb shell am broadcast -a shizuwall.PROFILE -n com.arslan.shizuwall/.receivers.ProfileControlReceiver --es profile "Work"
```

## Сборка из исходников

Проект собирается с помощью Gradle Wrapper и Android SDK:

```bash
./gradlew assembleDebug
```

Отладочные сборки используют суффикс `.debug` и могут устанавливаться вместе с релизной версией. Для релизных сборок нужна собственная конфигурация подписи.

## Отказ от ответственности

AndWall предоставляется **«как есть»**, без каких-либо гарантий. Он опирается на расширенные системные разрешения, и разработчик не несёт ответственности за нестабильность системы, потерю данных или побочные эффекты блокировки сети. Обязательно проверяйте, какие приложения вы блокируете.

Этот форк распространяется только через [этот репозиторий GitHub](https://github.com/hsushjk/AndWall). APK из других источников не связаны с этим проектом, используйте их на свой страх и риск. У AndWall нет официального сайта, и он не публикуется в Google Play или F-Droid.

Разрешение `INTERNET` используется только для сопряжения через беспроводную отладку (LibADB).
