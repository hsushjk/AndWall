## Совместимость

Android 11 и выше, а также один из следующих бэкендов:

- **VPN**: встроенный локальный VPN-бэкенд, не требует настройки и дополнительного приложения (только приложения текущего пользователя)
- **Shizuku** (поддерживаются форки)
- **LibADB**: сопряжение по беспроводной отладке, компьютер не нужен
- **Root**

Новые установки по умолчанию используют бэкенд **VPN** и режим брандмауэра **Белый список**, поэтому приложение готово к работе сразу после установки. Другие бэкенды можно выбрать позже в **Настройки → Бэкенд и рабочий режим**.

## Почему AndWall

- **Режим VPN не требует привилегированной настройки**: достаточно один раз разрешить системный VPN — без Shizuku, без ADB, без root.
- **Управление по приложениям**: блокировка сети для каждого приложения, включая копии в рабочем профиле и клонах в цепных режимах.
- **Приватность**: приоритет офлайн-работы, без аналитики, без телеметрии и без удалённого VPN-сервера — туннель полностью локальный, все пакеты отбрасываются.
- **Быстрый доступ**: плитка быстрых настроек, виджет и плавающая кнопка.
- **Автоматизация**: управление через broadcast-команды, отправляемые из adb, Tasker, MacroDroid и подобных.

## Как это работает

Только бэкендам Shizuku, LibADB и Root нужен привилегированный сопровождающий компонент. Они управляют **chain 3** службы connectivity Android — платформенным механизмом, который контролирует сетевой доступ для каждого пакета:

```bash
cmd connectivity set-chain3-enabled true                                # включить брандмауэр
cmd connectivity set-package-networking-enabled false <package.name>   # заблокировать
cmd connectivity set-package-networking-enabled true <package.name>    # разблокировать
cmd connectivity set-chain3-enabled false                               # выключить брандмауэр
```

Android сбрасывает эти правила после перезагрузки устройства.

### VPN-бэкенд

VPN-бэкенд — это локальное tun-устройство `VpnService`, которое перехватывает только те приложения, которые вы выбрали для блокировки, и отбрасывает все полученные пакеты. Ему нужен только один системный диалог разрешения, никакой другой настройки не требуется. Новые установки по умолчанию используют этот бэкенд вместе с режимом брандмауэра **Белый список** (выберите приложения, которым разрешён доступ в сеть, остальные блокируются); изменить это можно в **Настройки → Бэкенд и рабочий режим**.

После перезагрузки туннель автоматически запускается снова; если при включённом брандмауэре процесс приложения был завершён, защита восстанавливается при следующем открытии AndWall. Если на устройстве настроена блокировка экрана, поддерживается режим блокировки экрана (туннель следует за состоянием блокировки).

Ограничения VPN-бэкенда: он работает только с приложениями текущего пользователя (без копий в рабочем профиле и клонов), правила «только мобильные данные» и режимы на основе определения переднего плана не поддерживаются, а набор блокируемых приложений поддерживается без цепочек брандмауэра по UID. Если эти возможности нужны, продолжайте использовать Shizuku, LibADB или Root.

## Изменения в этом форке

AndWall — это форк [ShizuWall](https://github.com/AhmetCanArslan/ShizuWall). Этот форк добавляет:

- **VPN-бэкенд**: бэкенд брандмауэра без настройки, для работы которого достаточно подтвердить системный диалог разрешения.
- **Настройки по умолчанию для новых пользователей**: бэкенд VPN, режим брандмауэра «Белый список» и скрытие приложений без доступа к сети.
- **Обновлённый процесс первого запуска**: приветственный сценарий и выбор режима теперь упоминают все четыре бэкенда.
- **Адаптация интерфейса для режима VPN**: режимы брандмауэра и функции, которые не может предоставить VPN-бэкенд, скрыты, а режим брандмауэра заменяется на «Белый список».
- **Ребрендинг, обновлённые пункты настроек и переводы**, а также более подробные списки изменений и проверки обновлений для этого форка.

## Автоматизация

Каждый broadcast требует активного бэкенда. `apps` — это список ключей приложений через запятую: одно имя пакета означает пользователя 0, а ключ с префиксом (например, `150:com.example.app`) — копию в этом рабочем профиле или пространстве клонов.

### Брандмауэр: `shizuwall.CONTROL`

| Параметр | Тип | |
|---|---|---|
| `state` | boolean, обязательный | `true` = заблокировать, `false` = разблокировать |
| `apps` | string, необязательный | Приложения, которые нужно заблокировать или разблокировать. Если его опустить, broadcast включает или выключает брандмауэр целиком. |

```bash
# включить брандмауэр (state false выключает его)
adb shell am broadcast -a shizuwall.CONTROL -n com.arslan.shizuwall/.receivers.FirewallControlReceiver --ez state true

# заблокировать приложение и его копию в рабочем профиле (state false разблокирует их)
adb shell am broadcast -a shizuwall.CONTROL -n com.arslan.shizuwall/.receivers.FirewallControlReceiver --ez state true --es apps "com.example.app,150:com.example.app"
```

При наличии `apps` выбор в приложении синхронизируется: `state true` отмечает эти приложения и включает брандмауэр, если он был выключен; `state false` снимает отметку и оставляет брандмауэр включённым. В режиме белого списка `apps` указывает на список разрешённых, поэтому смысл двух состояний меняется на противоположный.

В режиме VPN broadcast работают так же, но `apps` должен ссылаться только на приложения текущего пользователя; ключи рабочего профиля пропускаются.

### Новое приложение: `shizuwall.APP_INSTALLED`

Сообщает о только что установленном приложении, чтобы политика и уведомление для новых приложений применялись к нему так, как если бы AndWall сам обнаружил установку. AndWall видит установки только в своём профиле пользователя, поэтому остальные профили нужно охватывать этим способом.

```bash
adb shell am broadcast -a shizuwall.APP_INSTALLED -n com.arslan.shizuwall/.receivers.AppInstalledReceiver --es apps "com.example.newapp"
```

Пока брандмауэр выключен, правила не применяются. Приложения без разрешения `INTERNET` игнорируются.

### Профиль: `shizuwall.PROFILE`

Активирует сохранённый профиль: применяет выбор приложений этого профиля, режим брандмауэра, режимы отдельных приложений и настройку *Показать системные приложения*.

| Параметр | Тип | |
|---|---|---|
| `profile` | string | Имя профиля, совпадающее с именем в панели профилей. |
| `profile_id` | string | Внутренний ID; проверяется первым и не зависит от переименования. В диалоге **Автоматизация** этого профиля показана готовая команда. |
| `force_enable` | boolean, необязательный | Включает брандмауэр после переключения, даже если он был выключен. |

Нужно указать хотя бы одно из значений: `profile` или `profile_id`. Если не совпадает ни одно, ничего не меняется, а об этом сообщает toast.

```bash
adb shell am broadcast -a shizuwall.PROFILE -n com.arslan.shizuwall/.receivers.ProfileControlReceiver --es profile "Work"
```

## Сборка из исходного кода

Проект собирается с помощью Gradle Wrapper и Android SDK:

```bash
./gradlew assembleDebug
```

Отладочная сборка использует суффикс `.debug` и может устанавливаться одновременно с релизной. Для релизной сборки нужна собственная конфигурация подписи.

## Отказ от ответственности

AndWall предоставляется **«как есть»**, без каких-либо гарантий. Он использует расширенные системные разрешения, и разработчик не несёт ответственности за нестабильность системы, потерю данных или побочные эффекты блокировки сети. Обязательно проверяйте, какие приложения вы блокируете.

Этот форк распространяется только через [этот репозиторий GitHub](https://github.com/hsushjk/AndWall). APK из любых других источников не связаны с проектом, и вы используете их на свой риск. У AndWall нет официального сайта, и он не публикуется в Google Play или F-Droid.

Разрешение `INTERNET` запрашивается только для сопряжения по беспроводной отладке (LibADB).
